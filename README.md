# Робота з базою даних за допомогою JDBC в Java

Цей проєкт є виконанням практичного завдання з налаштування підключення до реляційної бази даних **PostgreSQL** за допомогою **JDBC (Java Database Connectivity)**. У проєкті реалізовано базові операції **CRUD** (Create, Read, Update, Delete) з дотриманням чистих архітектурних підходів та оптимізації пам'яті.

## 🚀 Стек технологій
* **Java** (версія 17/21)
* **PostgreSQL** (версія 15/16/17)
* **JDBC Driver** (`org.postgresql:postgresql`)
* **Maven** (система збирання проєкту)
* **IntelliJ IDEA** (середовище розробки)

## 📁 Структура проєкту
Проєкт реалізовано відповідно до архітектурного шаблону **DAO (Data Access Object)**:
* `DatabaseConnector.java` — менеджер підключення до БД (керує `DriverManager`).
* `Employee.java` — клас-модель (POJO), що описує сутність співробітника. Оптимізований за принципом **Memory Layout** (групування посилальних типів перед примітивами) для зменшення втрат пам'яті (padding).
* `EmployeeDAO.java` — клас взаємодії з БД, що виконує SQL-запити через `PreparedStatement` та безпечно повертає результати.
* `DaoOperationException.java` — власний неконтрольований виняток (`RuntimeException`) для централізованої обробки помилок шару даних із передачею першопричини (`cause`).
* `Main.java` — точка входу для демонстрації роботи програми та CRUD-операцій.

## 🏗️ Особливості реалізації та оптимізації
1. **Безпека грошових типів**: Для збереження зарплати (`salary`) замість неточного типу `double` (`FLOAT`) використано **`BigDecimal`** (`NUMERIC`), що запобігає помилкам округлення.
2. **Гнучкість ідентифікаторів**: Поле `id` переведено на клас-обгортку **`Integer`**, що дозволяє сутності мати значення `null` до моменту її збереження в базу даних.
3. **Автоматичне отримання ключів**: Під час операції `INSERT` (`addEmployee`) реалізовано повернення згенерованого базою даних `id` через `Statement.RETURNED_GENERATED_KEYS` та його автоматичне встановлення в об'єкт Java.
4. **Контроль Null-значень**: Метод `getEmployeeById` повертає контейнер **`Optional<Employee>`**, що гарантує захист від `NullPointerException` на стороні клієнтського коду.
5. **Оптимізація викликів**: Метод `getAllEmployees` повертає конкретну реалізацію списку **`ArrayList<Employee>`** замість інтерфейсу за рекомендацією оптимізації CPU-ресурсів (уникнення оверхеду динамічного диспатчингу, де це не потрібно).

## 🛠️ Скрипт для створення таблиці

Для створення необхідної структури в pgAdmin (база даних `kolkova_tan`) було виконано наступний скрипт (з урахуванням точних фінансових обчислень):

```sql
CREATE TABLE employees (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    age INTEGER NOT NULL,
    position VARCHAR(100),
    salary NUMERIC(15, 2) NOT NULL -- Використовуємо точний тип замість FLOAT
);
```
